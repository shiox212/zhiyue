# 实验五 DeepSeek 图书知识助手与 RAG

整合版本使用统一AUTO助手，优先检索站内书目与项目资料，资料不足时分区补充通用知识。
课程源码入口为[main](https://github.com/shiox212/zhiyue/tree/main)，
版本和运行包关系见[交付状态](final-state.md)，准确提交CI和实验结果见[证据索引](evidence/evidence-index.md)。

## 使用与回答模式

站内内容页点击右下角“问问 AI”或顶部“AI 阅读助手”打开面板，收起按钮、再次点击入口或 Escape 可收起；收起后保留当前应用内存中的草稿、问答及进行中的请求。桌面支持展开与全页，小屏使用模态面板。
`/assistant` 保留完整页面，登录页不显示入口。访客可打开面板并点击“登录后提问”，登录后回到原页面；访客不发送受保护的状态或问答请求。
问答要求登录，POST还要求CSRF。共享Pinia会话在面板卸载与路由跳转后保留，刷新应用、退出或切换账号后清空，并忽略旧请求迟到结果。清空对话只丢弃本地显示，不保证取消已发送的服务商请求。

| 模式 | 回答范围 | 依据与限制 |
| --- | --- | --- |
| `AUTO`（界面唯一策略，接口默认） | 先检索公开书目和项目资料，再决定回答分区 | 命中最多发送3段；保留最强真实图书命中，书卡最多3本、服务端去重；无命中生成通用知识；不足时可返回独立generalSupplement |
| `LIBRARY`（旧接口兼容） | 仅站内书目和项目资料 | 无命中返回 `NO_EVIDENCE`，不调用模型；不显示通用补充 |
| `GENERAL`（旧接口兼容） | 通用文学与阅读知识 | 跳过检索、引用为空；标注非站内、非实时联网 |

历史显示问题、结果与回答边界标签，不发给模型；每次请求仍是单次独立问答，最多一次生成，无自动重试。连接失败仅提供手动重新连接或编辑重发，不把检索/上游故障伪装为成功无命中。
站内引用可展开原文，图书引用提供 `/books/{bookId}` 详情链接，ID 由服务端命中资料重建。
简介不等于图书全文，引用存在不能保证结论正确；通用知识也可能有误，不代表联网核实或站内收录。

## 启动与配置

先按[环境说明](setup.md)配置自己的MySQL和JWT，并使用5179/18085启动前后端。
AI生成需要在服务端本机配置DEEPSEEK_API_KEY，可选DEEPSEEK_MODEL=deepseek-flash，
配置变更后重启后端。未配置Key时普通图书功能仍可使用，助手提示生成不可用。
密钥不能填入公开模板或前端环境变量。
已持有M25的用户按[本机运行包说明](final-state.md#已有本机演示包)使用；源码新库没有137本演示馆藏。

这里的“OpenAI 兼容”指请求协议和 Java SDK：依赖 `com.openai:openai-java:4.69.3`，
请求固定发送至 `https://api.deepseek.com`，使用 DeepSeek Key 与模型，不需要 OpenAI 账户。
使用 Chat Completions，System / User 分离，JSON 输出，关闭 thinking，最多 1200 输出 token，
40 秒超时，不自动重试，避免重复消耗。前端本接口等待上限为 55 秒。

## 从问题到回答

1. 已登录用户提交问题；Spring Security 检查登录与 CSRF。
2. `LearningAssistant.ask(userId, question, mode)`检查输入，拒绝空白/纯标点；mode省略或null按AUTO。AUTO和LIBRARY检索项目资料与公开图书元数据，GENERAL跳过检索。
3. `DocumentChunker` 按段落与 Unicode 字符切分；长段最大 480 字符，重叠 60 字符。
4. `TfidfIndex`将英文词和中文相邻双字词转为TF-IDF向量。一般模糊检索最低余弦分0.13；完整书名或作者匹配可越过该阈值并获得排序优先级，兼容《诗经》《简·爱》和同名异作者。加权分数不是准确率，别名/同义改写召回仍有限。
5. 合并两类命中取最多3段，AUTO优先保留最强真实图书命中。AUTO无命中使用通用提示词和空references；LIBRARY无命中不调用模型。命中时把当前问题和片段组成User JSON，可在同一次生成内提供独立generalSupplement，不二次请求。
6. `DeepSeekModel` 通过真实 Java SDK 请求模型，返回文本、模型名、请求编号与 token 计数。
7. `AnswerVerifier`核对JSON、1至3个唯一资料编号及连续逐字6至480字符引句；bookId由服务端重建，不接受模型指定的链接。通用回答要求引用为空；通用补充不得携带资料编号、引文标记或URL。不合规返回UNVERIFIED并隐藏原输出；拒绝日志仅含固定原因枚举，不记录问题、模型文本或异常内容。
8. Vue 以纯文本显示回答，资料标题和原文由服务端知识库提供，用户可以展开核对。

这里用的是本地统计向量，**没有调用神经网络 embedding API、没有部署向量数据库**。
小语料足以演示分块、向量化、检索、提示词增强；同义改写和复杂问题的召回仍有限。
引用存在并不保证回答在语义上正确，必须人工对照原文；测试中保留了这一反例。

## 资料来源与更新

资料白名单位于 `src/main/resources/knowledge/zhiyue-guide.json`，当前 6 篇说明、14 个片段。
资料由AI按项目代码整理，修订时应核对对应源码与事实；不自动扫描磁盘、用户上传文件或本机配置。
修订增加受控数据库查询，仅投影图书 ID、书名、作者、分类、简介；不读取用户资料、书架、评论、密码或配置，不发送整库。
绑定问题和关键词，优先匹配完整书名/作者，候选上限 20 条；分块后仍用 TF-IDF 筛选并提升完整匹配优先级，召回有限，不保证查全。
状态接口的 documents/chunks 只描述项目资料白名单，不包含动态图书数量。
修改资料后应检查事实与保密范围，再重启服务重新建立索引。

## 接口与状态

| 接口 | 行为 |
| --- | --- |
| GET /api/assistant/status | 需登录；返回配置是否存在、模型名、资料数量，不返回 Key |
| POST /api/assistant/ask | 需登录与CSRF；请求体为 `{ "question": "《简·爱》的作者和简介是什么？", "mode": "AUTO" }`；AUTO为默认，兼容LIBRARY / GENERAL，省略或null按AUTO |

`ANSWERED` 表示格式和引用检查通过；`GENERAL_KNOWLEDGE` 表示通用知识、无站内引用；`NO_EVIDENCE` 表示未调用模型；
`INSUFFICIENT` 表示模型判断资料不足，展示固定系统说明；`UNVERIFIED` 表示模型输出未通过校验。
接口错误使用实际 HTTP 错误码：输入 400、未登录 401、CSRF 403、限流 429、
不完整模型输出 502、缺少配置或上游失败 503。错误详情不包含 Key 或服务商原始响应。

每个用户每分钟最多 5 次模型请求，全服务最多同时 2 次；这是单实例内存限制，
不是分布式生产限流。问题最大 1000 字符。正则输入拦截只覆盖明显越界指令，不能保证抵御全部注入。
没有模型工具执行、用户私有数据查询、自动操作账号或回答持久化功能；会话内历史不作为模型上下文。

## 验证与限制

自动测试使用H2或模型fixture；真实MySQL只读检索和真实模型请求另行记录，不能相互替代。
完整书名被短前缀书名抢先排序的缺陷已修复，并保留回归测试。
真实站内回答、AUTO无命中通用回答和部分资料不足分区补充已有证据。
两次AUTO页面没有采集网络token/requestId等元信息，不推算计费或耗时。

真实书卡进入详情后重开，原两条问答保留。引文展开、跳转、重开后再次展开另以历史真实响应回放验证，
回放属于模拟交互，不能当作第三次真实生成。证据范围见[索引](evidence/evidence-index.md)。

### 模型失败与提示词对照

基础实验使用“本项目Redis默认过期时间”这一错误前提提问。无资料基线推测常见过期值，
但项目没有使用Redis；加入检索原文与固定System规则的独立对照请求拒绝给出该值。
另有真实输出因引用校验失败被隐藏，未保存原输出的请求不能事后断言具体语义错误。
提示词明确同一来源的多个事实应合并为一个citation后，后续真实请求取得可核对的站内引用。
严格资料编号和逐字引用规则保持，没有为通过测试而放宽校验。

原始输出、请求记录、截图与失败日志保存在课程实验归档中。
模型回答与检索相关性仍可能有误；书卡检索噪声、别名召回和手机真机交互仍有改进空间。
旧503 SDK异常和历史进程退出的精确原因未知，保留原始记录，不根据一次后续成功推断原因。
